# 第二阶段：数据回测搭建计划

更新时间：2026-03-20
状态：正式启动

## 一、第二阶段目标

目标不是继续优化文案，而是把第一阶段的经验规则转成：
1. 可显式定义的策略规则
2. 可批量跑历史样本的回测框架
3. 可量化评估的结果指标
4. 可反向修正第一阶段选股/买点/卖点逻辑的数据基础

第二阶段优先追求：
- 实用性
- 准确性
- 可解释性
- 可扩展性

暂不优先考虑：
- 节省接口调用
- 极致轻量
- 分钟级高频复杂度

---

## 二、第二阶段拆分为 4 个子阶段

### Phase 2A：规则显式化
把当前经验判断拆成结构化策略定义：
- 主线趋势
- 轮动补涨
- 埋伏观察

每个策略都要拆成：
- 样本池条件
- 入选条件
- 排除条件
- 买入触发
- 卖出触发
- 失效条件

### Phase 2B：数据层搭建
建立回测所需的标准化数据访问与缓存层：
- 股票基础信息
- 日线行情
- 复权因子
- daily_basic
- 行业/概念映射
- 指数数据
- 涨跌停/停牌/交易状态
- 财务与业绩数据（先预留接口）

### Phase 2C：回测引擎基础版
支持：
- 按日期扫描候选
- 记录信号
- 模拟买入/卖出
- 统计持有期收益
- 生成回测结果表

### Phase 2D：结果分析与策略修正
输出：
- 胜率
- 平均收益
- 盈亏比
- 最大回撤
- 不同市场环境表现
- 不同策略表现
- 不同行业表现
- 不同买入区间表现

## 三、第二阶段第一批正式范围

### 1. 先做日频回测
不碰分钟级。

### 2. 先做 3 类策略
- 主线趋势
- 轮动补涨
- 埋伏观察

### 3. 先做 3 类持有期
- 次日收益
- 3日收益
- 5日收益

### 4. 先做 3 类买点验证
- 收盘入选，次日开盘参考
- 次日建议区间触发
- 不追高过滤后再买

---

## 四、第二阶段要回答的核心问题

1. 哪类候选策略历史胜率最高？
2. 哪类策略在 weak / neutral / strong 市场环境下更有效？
3. 哪类行业最适合用户当前风格？
4. 买入区间怎么给，历史表现最好？
5. 哪些票经常“逻辑对但不走出来”？
6. 哪些票经常“区间合理但弹性不足”？
7. 哪些条件组合最适合做候选池收口？

## 五、第二阶段初始文件规划

- `backtest.yaml`：回测参数配置

### quant/
- `strategy_rules.py`：策略显式规则

- `run_backtest.py`：运行入口

### outputs/
- `backtests/`：回测结果输出目录

## 七、与第一阶段的衔接原则

1. 第一阶段继续可用，不废弃
2. 第二阶段是“研究层”，不是替换第一阶段
3. 等第二阶段验证出有效规则后，再反向喂给第一阶段日常选股

---

## 八、当前已确认的基础规则（从第一阶段继承）

- 房地产相关方向硬排除
- 排除 ST / 退市 / 已持有 / 创业板（当前阶段）
- 候选池不因“之前推荐过”自动屏蔽
- 建议买入区间不是买入指令，而是“到区间 + 盘面确认”
- 当前主要交易周期：隔日到 3~5 日
